# 1. ANSWER: direction is derived from the regime label. And there is no strategy.

## 1a. Direction comes from the regime, via a trend-following rule

`system2/.../live_signal_producer/producer.py:470-483`:

```python
def _resolve_direction(self, strategy, regime, feats) -> str | None:
    """Resolve an ``auto`` direction from the regime (trend-follow / range-fade)."""
    if strategy.direction in ("long", "short"):
        return strategy.direction
    if regime == "Trending-Up":
        return "long"
    if regime == "Trending-Down":
        return "short"          # <-- your 13 of 13
    if regime == "Ranging":
        pos = float(price_position_20(feats).iloc[-1])
        return "short" if pos > 0.5 else "long"
```

Direction **never reaches this code from your `ScoredSignal`.** It is set to the literal string
`"auto"` at `signal_builder.py:165` when the manifest is parsed, because
`regime_strategy_map.json` carries only `strategy_id`, `variant` and `rank` — no direction field.
`signal_builder.py:17-18` says so in its own docstring:

> *"This format carries no direction or SL/TP config, so direction is `auto` (resolved by the
> producer from regime + price position)"*

**This is your branch 1.** `Trending-Down → short`, deterministically, every time. Your p = 0.001 is
not improbable at all — it was certain.

**There is no entry trigger.** No oscillator, no %K crossing, no divergence test, no setup

`Range_Stochastic_Divergence` is a **label attached to an ID**, not behaviour. Your backtest measured
a mean-reversion oscillator. Production runs *"go short everything in a downtrend, whenever we
