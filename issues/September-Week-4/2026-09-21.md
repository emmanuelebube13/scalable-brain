# 2026-09-21

## Committed dashboard bundle was built in dev mode; deploying it broke every GCS-backed view

**Found while:** owner reported dashboard errors (Assets "HTTP 404", status strip all
UNKNOWN/stale, Strategy House "no catalogue", Factory panel "System 1 has never published a
health object") the night after the 2026-09-21 trades-fix deploy.
**Where:** umbrella repo, `cloud/telemetry-web/static/` as committed in `10ef44b`
("Dashboard observability improvements Tasks 1-6"); served as Cloud Run revisions
00109–00110.
**What:** The static bundle committed in `10ef44b` was built **without
`VITE_DATA_MODE=cloud`** (its inlined env carries an empty value), so `connection.js` ran
in local-dev mode and fetched the localhost proxy paths — `/api/system2/*`,
`/api/system3/*`, `/api/signal`, `/s1health.json`, `/strategy.json` — none of which exist
on Cloud Run. Every GCS/status-derived view blanked; DB- and broker-backed panels kept
working, which made it look like a data-pipeline failure rather than a build flag. The
2026-09-21 02:08Z deploy (`--source .`, backend trades fix) faithfully shipped the broken
committed bundle; the pre-deploy revision had been serving an older cloud-mode bundle,
masking the defect since `10ef44b` landed.
**Evidence:** Cloud Run request logs 2026-09-22 00:40–00:55Z: repeated 404s on exactly
those paths. `grep -oE 'VITE_DATA_MODE[^,;]{0,20}'` — broken bundle `index-CIpqgoc0.js`:
`VITE_DATA_MODE=""…`; rebuilt `index-m4aVbz8v.js`: `VITE_DATA_MODE:"cloud"`. Backend was
healthy throughout (all `/api/*` endpoints 200 via curl with token).
**Resolution (same night):** rebuilt with `VITE_DATA_MODE=cloud`, replaced `static/`,
commit `2e570dc`, deployed revision `telemetry-dashboard-00111-hpg`, verified live: served
index references `index-m4aVbz8v.js`, `/api/telemetry` 401 JSON, all frontend-consumed
endpoints 200, trades fill-identity merge still working (trade 2721/2722 attributed).
**Why it matters:** "rebuild the bundle" without the mandatory mode flag produces a bundle
that works on the dev machine and silently dies in production — the exact trap
`DEPLOY.md` documents ("cloud mode is mandatory"). Review of frontend-bundle commits should
verify the inlined `VITE_DATA_MODE` value in `static/assets/index-*.js`, not trust the
commit message.
**Not done:** Did not identify which session built `10ef44b`'s bundle. Did not mount
`routes/alerts.py` (exists, unmounted, and its error path returns `[]` — conflates absent
with empty, violating the honesty rule; needs review before mounting). Revision 00110-nj6
(owner, 12:41Z, set `TELEMETRY_OBJECT=telemetry/latest.json`) is superseded; both
telemetry objects publish fresh and identically, so that env change was neither cause nor
harm.
