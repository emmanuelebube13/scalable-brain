# Issues — 2026-08-30

## 1. `model001_ingest.log` recreates itself at the repo root on every ingest run

**Status: OPEN. Not fixed — recording the cause so the next sweep does not just delete it again.**

**Found while:** running the structure-warden pass over the Gate-1 signal ledger change set.
Not caused by that change.

**Where:** `src/ingestion/multi_timeframe_ingest.py:449`

```python
parser.add_argument("--log-file", default="model001_ingest.log")
```

**What:** the default is a *relative* path, so every ingest run writes the file into
whatever the current working directory is. The hourly cron does `cd "$REPO"` before running
the ingest (`shell/cron_hourly_signals.sh`), so in practice that directory is always the
repo root — which `STRUCTURE.md:23-25` closes to new files ("Nothing new at the repo root").

**Evidence:** present on disk today, mtime 2026-08-30 08:15, untracked. It is invisible in
`git status` because `*.log` is gitignored, which is why it keeps surviving reviews.

**Why it matters:** this is the third occurrence. It was swept out on 2026-08-28
(`task/2026-August-week3/deliverables/CLEANUP/CLEANUP-2026-08-28.md`) and again in the
July T7 deliverable, and it regenerated both times within hours. Deleting the file is not a
fix — the default recreates it on the next hourly run, so each cleanup only schedules the
next recurrence. The root allowlist is enforced by review, and this defeats review by being
gitignored.

**Fix would be:** default the argument to an absolute path under the top-level `logs/`
directory (where `STRUCTURE.md:58` says runtime logs belong), resolved from the module's
own location the way `REPO_ROOT` is derived elsewhere — not from the CWD.

**Not done:** I did not change the default, and I did not delete the file. Changing an
ingest CLI default is outside the ledger change set and belongs with whoever next touches
MODEL-001. I also did not check whether any cron, log-rotation config, or doc references
the current root path and would break if it moved.
